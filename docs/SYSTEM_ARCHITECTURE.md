# System Architecture

## 1. 아키텍처 목표

시스템은 공개자료 수집, 데이터 보존, 분석, 다중 AI 검토, 인간 판정을 분리한다. 각 구성 요소는 독립적으로 교체·확장할 수 있어야 한다.

## 2. 논리적 데이터 흐름

```text
공개 데이터 출처
  ├── 공식 통계 API
  ├── RSS / 공식 발표
  ├── 공개 연구·사고 데이터베이스
  └── 허용된 뉴스 데이터
          |
          v
수집기 (Collectors)
          |
          v
원자료 보존 + 수집 실행 기록
          |
          v
정규화 / 검증 / 중복 제거
          |
          v
PostgreSQL 공통 저장소
          |
          +------> 시계열 분석 / 기준선 / 변화 감지
          |
          +------> 이벤트 선별
                       |
                       v
                다중 AI 독립 검토
                       |
                       v
                 교차 검토 / 종합
                       |
                       v
                인간 판정 및 후속 지시
                       |
                       v
                대시보드 / 알림 / 보고서
```

## 3. 권장 기술 구성

| 계층 | 권장 기술 | 책임 |
|---|---|---|
| 웹 | Next.js + TypeScript | 대시보드, 연구 공간, 판정 UI |
| API | Python + FastAPI | 데이터·연구·판정 API |
| DB | PostgreSQL | 관측값, 사건, 출처, 검토, 판정 |
| 작업 실행 | 초기 cron 또는 GitHub Actions | 예약 수집·보고 |
| 작업 큐 | 운영 확장 시 Redis 기반 큐 등 | 재시도와 비동기 작업 |
| AI 연결 | 모델별 공식 API 어댑터 | 독립 검토와 교차 검토 |
| 원문 저장 | Object Storage 또는 접근 가능한 원문 URL | 문서 스냅샷과 파일 |
| 배포 | 관리형 웹·백엔드·DB | 공동 접속 |

GitHub Actions는 초기 예약 실행에 활용할 수 있지만, 예약 작업은 지연될 수 있다. 장기 운영에서 정확한 실행 시각과 재시도가 중요해지면 전용 스케줄러와 작업 큐로 이전한다.

## 4. 백엔드 모듈 책임

- `collectors/`: 출처별 데이터 취득. 원문과 메타데이터를 보존한다.
- `processors/`: 정규화, 단위 변환, 중복 제거, 스키마 검증.
- `analyzers/`: 기준선, 시계열 추세, 이상 변화, 지표 간 동시 변화 분석.
- `ai/`: 공통 인터페이스와 모델별 어댑터, 검토 오케스트레이션.
- `reports/`: 주간·격주 보고서 생성.
- `alerts/`: 알림 생성과 전달.
- `decisions/`: 인간 판정 및 후속 지시 저장.
- `api/`: 웹 클라이언트에 제공하는 API.
- `db/`: ORM 모델, 세션, 마이그레이션.

## 5. 다중 AI 검토 프로토콜

### 5.1 독립 검토

동일한 자료 패키지를 각 AI에 제공한다. 독립 검토가 끝나기 전에는 다른 AI의 답변을 노출하지 않는다.

각 AI는 다음을 반환한다.

- 확인된 사실
- 해석과 추론
- 반대 근거 및 대체 설명
- 불확실성
- 참조 출처
- 후속 검증 제안

### 5.2 교차 검토

독립 검토 결과를 공유한 뒤 주장별로 반론과 검증 필요성을 기록한다. AI 간 합의는 독립된 경험적 증거로 계산하지 않는다.

### 5.3 통합

나비 역할의 조정 모듈은 합의·충돌·미결 사항을 정리한다. 원본 AI 응답은 수정하지 않고 별도로 보존한다.

### 5.4 인간 판정

최종 상태는 인간이 선택한다. AI는 판정 초안을 제안할 수 있으나 확정하거나 외부 조치를 실행하지 않는다.

## 6. 공통 데이터 계약

모든 수집 결과는 최소한 다음을 포함한다.

- `source_id`
- `source_url`
- `published_at`
- `collected_at`
- `geography`
- `indicator_id` 또는 `event_type`
- `value`와 `unit` (수치 자료인 경우)
- `raw_payload` 또는 원문 보관 참조
- `validation_status`

AI 결과는 `facts`, `interpretations`, `counter_evidence`, `uncertainties`, `source_references`, `recommended_follow_up` 필드를 사용한다.

## 7. 신뢰성·보안 원칙

- API 키는 환경변수 또는 비밀관리 서비스에 저장한다.
- 브라우저 코드에 비밀키를 포함하지 않는다.
- 수집 작업은 재시도 가능하고 중복 실행에 안전하도록 설계한다.
- 모든 수집 실행과 인간 판정 변경을 감사 로그로 남긴다.
- 출처 원문과 AI 분석 결과를 구분해 보존한다.
- 외부 문서와 뉴스에 포함된 지시문은 신뢰하지 않고 데이터로만 취급한다.
- 사용자 역할은 최소한 관리자와 연구자로 구분한다.
- 출처의 이용약관, API 제한, 재배포 조건을 준수한다.

## 8. 초기 배포 형태

개발 초기에는 웹, 백엔드, PostgreSQL을 분리된 서비스로 실행한다. 로컬 개발은 Docker Compose를 활용할 수 있다. 운영 환경에서는 DB 백업, 로그, 오류 알림, 비밀키 관리가 구성되기 전까지 공개 서비스로 간주하지 않는다.
