# Source Catalog

## 1. 목적

이 문서는 MVP에서 사용할 미국 중심 공개자료 출처와 수집 우선순위를 관리한다. 실제 연동 전에 각 출처의 API 접근 조건, 이용약관, 갱신 주기, 재배포 조건을 확인해야 한다.

출처 목록은 확정된 API 연결 목록이 아니라 초기 후보 목록이다. 접근이 불가능하거나 이용 조건이 맞지 않으면 대체 출처를 검토하고 변경 이력을 남긴다.

## 2. 우선 연동 출처

## 3. 출처별 수집 지침

### 3.1 BLS

- 공식 문서: https://www.bls.gov/developers/
- 활용: 직종별 고용·임금·실업 관련 통계
- 저장: 시리즈 ID, 기간, 값, 단위, 계절 조정 여부, 발표 시점
- 유의: 지표별 정의와 시계열 개정 여부를 기록한다. 직종별 고용은 신입 채용 공고 수와 동일하지 않다.

### 3.2 EIA

- 공식 문서: https://www.eia.gov/opendata/
- 활용: 전력 수요, 발전량, 발전원 구성 등
- 저장: 지역, 기간, 전력 지표, 단위, 데이터 갱신 시점
- 유의: API 키 및 엔드포인트별 사용 조건을 확인한다. 전체 전력 수요만으로 AI의 기여분을 분리할 수 없다.

### 3.3 Indeed Hiring Lab

- 사이트: https://www.hiringlab.org/
- 활용: 채용 공고 추세와 AI 관련 노동시장 분석
- 수집: 공개된 데이터·API 접근 가능 여부 확인 후 연동
- 유의: 공개 지수의 정의, 국가·직종 범위, 표본 및 이용 조건을 확인한다. 접근이 제한되면 무단 스크래핑하지 않는다.

### 3.4 GDELT

- 사이트: https://www.gdeltproject.org/
- 활용: AI 관련 뉴스 및 정책 발표의 발견·추세 관찰
- 수집: 공개 API 및 데이터셋
- 유의: 보도량은 관심도·보도 활동의 지표이지 실제 사건 발생률이 아니다. 기사 중복과 출처 편향을 처리한다.

### 3.5 기업 공식 발표

초기 대상은 주요 AI 모델 제공 기업의 공식 뉴스룸, 연구·안전성 페이지, 시스템 카드 및 모델 문서다.

- 활용: 모델 출시, 기능 변경, 안전성 평가, 사용 정책 변경
- 우선순위: 공식 원문
- 유의: 기업 자체 주장은 독립 검증과 구분한다.

### 3.6 미국 정부 및 규제기관

초기 후보:
- NIST: https://www.nist.gov/
- Federal Register: https://www.federalregister.gov/
- 관련 연방 부처 및 규제기관의 공식 발표 페이지

활용:
- AI 관련 정책, 지침, 규칙 제정, 시행일
- 유의: 제안 규칙, 최종 규칙, 시행 중인 규정을 구분한다.

### 3.7 AI Incident Database

- 사이트: https://incidentdatabase.ai/
- 활용: 공개된 AI 사고·피해 사례 발견 및 분류
- 유의: 보고된 사례의 수는 실제 사고의 전체 발생률을 뜻하지 않는다. 동일 사건 중복과 사건 정의를 검토한다.

### 3.8 NIST 및 IEA

- NIST AI 관련 자료: https://www.nist.gov/artificial-intelligence
- IEA: https://www.iea.org/
- 활용: AI 위험 관리·평가·표준, 데이터센터 에너지 및 탄소 분석
- 유의: 보고서의 기준연도, 추정 방법, 지역 범위, 공개·재사용 조건을 기록한다.

## 4. 출처 승인 절차

새 출처를 등록하기 전에 다음을 확인한다.

1. 발행 기관과 원자료 제공 주체가 명확한가?
2. 원문 URL과 발표일을 보존할 수 있는가?
3. 측정 방법과 데이터 정의가 공개되어 있는가?
4. 갱신 주기와 과거 자료 접근이 가능한가?
5. API 이용 제한과 재배포 조건을 준수할 수 있는가?
6. 다른 독립 출처와 교차 확인할 수 있는가?

## 5. 출처 상태값

- `candidate`: 검토 대기
- `approved`: 수집 승인
- `active`: 자동 수집 중
- `paused`: 일시 중지
- `retired`: 사용 종료

## 6. 출처 변경 이력

출처의 URL, API, 데이터 정의, 접근 조건이 변경되면 기존 설정을 조용히 덮어쓰지 않는다. 변경일, 변경 내용, 영향받는 지표, 재처리 필요 여부를 기록한다.
